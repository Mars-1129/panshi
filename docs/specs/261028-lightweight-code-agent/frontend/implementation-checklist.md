# 前端实现与验收清单

## 设计和范围

- [ ] 页面属于正确的工作流：工作区、任务、审查、模板或设置。
- [ ] 没有把所有功能塞进一个聊天窗口。
- [ ] 每个页面只有一个主要动作，次要、取消、重试和危险动作层级清楚。
- [ ] 使用 RepoPilot token，不复制 OmniDirector 或第三方项目的视觉资产。

## 状态和数据

- [ ] loading、empty、error、success、disabled、blocked、stale、offline 都有设计。
- [ ] 页面状态来自 API/事件事实，不使用假计时器伪造进度。
- [ ] 事件有 schema、seq 和 runId 校验。
- [ ] 断线能显示已知状态并恢复缺失事件。
- [ ] 计划变化会重新请求审批。

## 交互和可访问性

- [ ] 所有交互控件有可访问名称。
- [ ] Tab 顺序与视觉和任务顺序一致。
- [ ] focus-visible 可见且不被 sticky 区域遮挡。
- [ ] 错误使用 `role="alert"` 或可感知的 live region。
- [ ] 状态不只依靠颜色。
- [ ] 触控目标接近 44×44px。
- [ ] `prefers-reduced-motion` 下仍能理解任务变化。

## 响应式

- [ ] 375、768、1024、1440 宽度通过检查。
- [ ] 手机端主动作、返回、审批和取消入口可达。
- [ ] 代码/diff/命令输出的局部横向滚动不会造成页面整体溢出。
- [ ] sheet、modal、固定底部栏不会遮挡焦点或输入。

## 性能

- [ ] 事件时间线和 diff 大列表使用虚拟化或分页。
- [ ] 代码编辑器、重型预览和图表按路由懒加载。
- [ ] 流式事件只更新受影响的区域。
- [ ] 主题和布局切换不产生明显闪烁或布局跳动。
- [ ] 使用 React Profiler 或浏览器性能工具定位瓶颈后再优化。

## 测试和证据

- [ ] view-model 有状态转换和边界测试。
- [ ] 任务创建、审批、运行、取消、失败恢复有 Playwright 流程。
- [ ] 至少覆盖空、加载、失败、成功、断线和窄屏截图。
- [ ] 记录 typecheck、lint、unit test、e2e 和 build 结果。
- [ ] 交付报告列出仍存在的限制，不把 fallback 或未验证状态写成成功。
