# 政企视觉语言（Gov / Enterprise Theme）

本文件说明 `apps/code-agent` 在 ui-kit-v4 之上叠加的**政企视觉层**
（[`src/panshi.css`](../../../apps/code-agent/src/panshi.css)）。目的是让同一套工厂组件在
政府 / 央国企语境下成立：严肃、克制、信息密度高、可离线运行。

## 1. 设计依据

参考公开的政务门户设计规范（[dsh-gov-portal · 政务服务门户设计规范][gov]）与政府采购公示的
界面规范附件，提炼出与本产品相关的六条：

1. 白色内容区 + 深蓝主导航 + 红色只做重点提示；
2. 模块容器以直角或小圆角为主，`1px` 实线边框，不用大面积阴影与玻璃；
3. 使用系统中文字体栈，正文与辅助信息层级清楚；
4. 表格表头用浅灰底、保留清晰边框，单元格内边距约 `0.7rem`；
5. 成功 / 处理中 / 失败 / 待审批必须**文字 + 颜色**同时表达；
6. 不依赖外部字体、样式框架或远程图片，保证离线与国产化环境可用。

[gov]: https://github.com/ExElectron/dsh-gov-portal/blob/main/docs/design-system.md

## 3. 字阶与控件度量

| 类别 | 取值 | 说明 |
| --- | --- | --- |
| 微标签 `--rp-fs-meta` | 11.5px | 哈希、时间、编号、kbd（下限） |
| 辅助 `--rp-fs-compact` | 12.5px | 表头、副标题、状态标签、说明 |
| 界面 `--rp-fs-ui` | 13.5px | 列表行、卡片正文 |
| 控件 `--rp-fs-control` | 15px | 正文、输入框；按钮固定 14px |
| 正文 `--rp-fs-body` | 15.5px | 长文本段落 |
| 面板标题 `--rp-fs-h3` | 18px | 弹窗标题、面板标题 |
| 工段标题 `--rp-fs-h1` | 28–32px | 工段名（clamp） |
| 指标 `--rp-fs-metric` | 28px | KPI 数字，等宽数字 |
| 控件高度 | 32 / 38 / 44px | `--rp-control-sm/md/lg`；≤640px 全部回到 44px |
| 圆角 | 4 / 6 / 8 / 999px | 控件 / 面板 / 容器 / 状态胶囊 |

规则：

- 中文正文不小于 13.5px；11.5px 只用于等宽标识与 kbd，不用于成句中文。
- 所有数字（KPI、哈希、耗时、编号）使用 `tabular-nums`，避免列宽跳动。
- 标题 `line-height: 1.24`，正文 `1.62`，说明文字 `1.5`。
- 全局 `letter-spacing: 0.012em`：微软雅黑在小字号下偏紧，轻微字距能提升可读性。
- 工段头是三级结构：上行标签（`工段 05 / 10 · Prototype & Contract`，11.5px）→ 工段名（28–32px）
  → 一句话说明（13.5px）；不要再用「一行里塞编号 + 大标题 + 英文副标题」的旧写法。

## 4. 对齐与换行（v4 组件的实际问题与修法）

| 问题 | 根因 | 修法 |
| --- | --- | --- |
| 「发票核验」被压成竖排单字 | `.role-head` 内标题与长锚点 id 抢宽度，缺少 `min-width: 0` | 标题 `nowrap + ellipsis`；原型卡把锚点标签换到第二行（`flex: 1 0 100%`） |
| 交付统计数字与标签挤在一行 | `.rs-value` / `.rs-label` 是 `span`，默认行内 | 改为 `display: block`，长文本值用 `.is-text` 降字号 |
| 巡航区左右面板高度不齐 | `.self-heal` 抢占第二行第一列 | 三个区块统一 `panel-head`，`.self-heal` 横跨整行 |
| 12 个角色卡出现 5/5/2 参差 | `auto-fill` 列数随宽度漂移 | 桌面 `--rp-role-card-min: 280px` → 4 列 × 3 行整除；1440 档降到 258px 保持 4 列 |
| 业务原型 7 个锚点难配平 | 单一 auto-fill 栅格 | 12 列栅格 + 按 `data-panshi-id` 指定跨度：5+4+3 / 3+3+3+3 |
| 产物行哈希与状态错位 | 继承 flex 的 `margin-left: auto` | 改为三列 grid（名称 / 哈希 / 状态），清除自动外边距 |
| 顶栏在 768px 溢出 | flex 子项默认 `min-width: auto` | `.factory-meta` 允许收缩，≤1024 只保留连接状态 |
| 12 张角色卡重复同一句「数据未接入」 | 说明写进了每张卡 | 提到 `.role-summary` 总述条，卡片只留工段号与预算状态 |
| 首屏被拉长到一屏以外 | 基线与最近运行各占一行 | `.panel-duo` 并排（1024 以下再堆叠） |

## 5. 使用方式

```ts
// main.tsx：先 kit，后政企层，顺序不能反
import "../../../ui-kit-v4/css/styles.css"
import "./panshi.css"
```

- 换主色 / 换深蓝：只改 `panshi.css` 第 1 节的 token；组件规则不感知颜色。
- 新增页面：优先复用 `.io-col` / `.role-card` / `.panel-head` / `.role-facts` 等既有结构，
  不要为单页复制颜色或写裸 `hex`。
- 需要「规则清单」类页面时，参考护栏链（`.rail-chain`）与工段执行合同（`.plan-flow`）：
  静态规则用列表表达，运行结果用状态胶囊表达，二者不混。

## 6. 交互与弹层

**新建运行弹窗（`.modal-*`）** 取代原来的右侧抽屉：

- 居中 580px，`8px` 圆角，遮罩 `--rp-overlay-bg`，进入动画 240ms `translateY(10px)+scale(0.985)` → 归位；
- 结构固定为 头（图标 / 标题 / 说明 / 关闭）→ 体（字段 + 提示 + 计数 + 审批边界）→ 脚（快捷键提示 + 取消 + 主操作）；
- 键盘：`Esc` 关闭、`Ctrl/⌘ + Enter` 提交、打开即聚焦标题；关闭恢复 `body` 滚动；
- 状态：必填未达 2 字时主按钮禁用；提交中显示 `正在创建…` 与 spinner；失败在弹窗内 `role="alert"` 呈现，不关闭；
- 移动端（≤640）转为底部抽屉：全宽、仅顶部圆角、`justify-content: flex-end` 的按钮组。

**Toast（`.toast-*`）** 用于瞬时反馈，不替代常驻错误：

- 右下 380px，4.2s 自动消失，可手动关闭，`role="status" aria-live="polite"`；
- 语义色只体现在左侧 3px 条与图标底色，正文保持中性；
- 触发点：创建成功/失败、Skill 未接入、写操作二次确认。

**过渡**

- 切换工段时 `.stage-enter` 重挂载并播放 240ms 上浮（`key={stageId}`）；
- 侧栏项、按钮、chip 用 120–160ms 的 background / border-color 过渡，不使用位移弹跳；
- `prefers-reduced-motion: reduce` 下全部动画置空。

## 6.5 单屏布局（桌面不滚动）

目标：**1600×900 / 1440×900 一屏放得下**，细节进弹窗；窄屏与矮屏允许滚动兜底。

- 工段视图是 `flex` 列：头部（kicker / 标题 / 说明 / 下一步）+ 退出条件 + `.stage-body`（`flex: 1; min-height: 0`）；
- **内容区不做 1680px 居中上限**：驾驶舱按可用宽度铺满（`.stage-container { width: 100%; max-width: none; margin: 0 }`），
  否则在 2560 / 3440 的屏幕上右侧会留出大片空白；窄屏再按断点处理；
- **输入 / 输出产物不再常驻页面**：改由头部「产物」按钮打开 `ArtifactsDialog`（当前产物 + 契约要求），
  这样每个工段省掉约 150px，也避免所有工段长得一样；
- 每个工段只有一个主视觉，互不复用：

| 工段 | 主视觉 | 布局 |
| --- | --- | --- |
| 00 | 工厂驾驶舱 | 引导条 + 4 KPI + 十工段链路 + 「基线事实 / 最近运行」并排 |
| 01–04 | 契约 + 计划链路 | 左：产物契约清单；右：5 步横向流程卡（≤1200 换 3 列/2 列） |
| 05 | 业务原型 | 原型窗口占满剩余高度，两行锚点卡 5+4+3 / 3+3+3+3；契约移入弹窗 |
| 06 | 角色栅格 | 总述条 + 4×3 角色卡 |
| 07 | 规则链 + 事件 | 左：7 道护栏（行拉伸填满）；右：阻断事件 + 证据字段 |
| 08 | 双擎质检 | 红/蓝/裁判三栏 + 巡航两栏 + 关键路径（6 步）+ 自愈链 |
| 09 | 证据交付 | 左：统计 + 证据链（内部滚动）；右：未验证项 + SkillPack + PR 草稿 |

- 矮屏策略：`@media (max-height: 800px)` 收起说明行、引导条与业务原型页头，标题降到 22px；
  仍溢出时 `.stage-view` 允许整页滚动，绝不裁切内容。

## 6.6 引导与后端对接

- **Onboard 条**（仅工段 00）：三步上手 + 「查看引导」，关闭状态写 `localStorage.rp-onboard`；
- **每页「下一步」**：`STAGE_GUIDE` 提供一句话的下一步动作，写在标题下方，不需要用户自己猜；
- **帮助弹窗**（顶栏 `?` 或页脚入口）分两个 tab：
  - 使用引导：4 步流程、快捷键、十工段可点击跳转；
  - 后端对接：`BACKEND_GAPS` 的 42 条缺口，按工段分组，标注「已渲染 / 空态 / 未覆盖」与建议的事件/字段。
- 新增后端能力时，先改 `view-model/factory-types.ts` 的 `BACKEND_GAPS` 与 `STAGE_ARTIFACTS`，
  再在对应工段渲染真实数据；不要先写组件再倒推字段。

## 7. 已知取舍

- 不引入 Noto Sans SC 等外部字体：政企内网与离线部署优先，沿用系统中文字体栈
  （`Segoe UI` → `Microsoft YaHei UI` → `PingFang SC`）。
- 不做玻璃 / 氛围光：深色主题保留，但同样是实底 + 1px 边框。
- 深色主题不是默认外观：政企演示与打印场景以浅色为主，深色用于长时间盯屏。
- KPI 与工段链路只在 Stage 0 出现，避免每个页面重复同一块导航信息。
- 弹窗没有做完整焦点陷阱（focus trap）：当前只有一个弹窗、字段少，依赖初始聚焦与 Esc 关闭；
  若后续出现嵌套弹窗，需要补 trap 与 `inert`。
